## 实测修正（2026-10-27 夜，真实账号跑通后推翻本文档前几节的部分结论）

> 用真实账号（烟台科技学院，41 门课）在电脑端逐跳验证，结论如下。**以下几节以本节为准。**

### 1. 裸 HTTP 走不通，必须在 WebView 里做

同一条课程中间页 URL：

| 执行环境 | 结果 |
|---|---|
| 真实浏览器（已登录） | 302 → `mooc2-ans/mycourse/stu?...&enc=<X>&t=<ms>`，课程页正常 |
| Node fetch（Cookie 完全一致，按域匹配/全平铺 × 2 个 host 共 4 组） | **一律返回登录页**（title=用户登录，35.8 KB） |

Cookie 从 12 个增加到 46 个后仍然失败。说明服务端在按请求特征（TLS 指纹 / `Sec-Fetch-*`）区分客户端，**改 Cookie 和改头都救不了**。

→ 作业列表这一步改为：**隐藏 WebView 加载课程页 → 读 `#workEnc` → 组装 URL → WebView 打开 → 读 DOM**。
→ 课程列表继续走 JSON API（`backclazzdata`，实测 41 门课全拿到，可用）。

### 2. `enc` 和 `stuenc` 是两个不同的值

点击课程页的 `a[title="作业"]`（其 `data-url="https://mooc1.chaoxing.com/mooc2/work/list"` 本身**不带参数**，参数由 JS 现拼），浏览器实际发出：

```
GET mooc1.chaoxing.com/mooc2/work/list
    ?courseId=…&classId=…&cpi=…&ut=s
    &t=<当前毫秒时间戳>
    &stuenc=<课程页 URL 里的 enc>
    &enc=<课程页隐藏 input #workEnc 的 value>
```

| 参数 | 正确来源 | 填错的后果 |
|---|---|---|
| `stuenc` | 课程页 URL 的 `enc` | 「无权限的操作！」 |
| `enc` | 课程页 `<input type="hidden" id="workEnc">` | 「无权限的操作！」 |
| `t` | 请求时现取的毫秒 | 「无权限的操作！」 |

本文档第 2、3 节写的「中间页会下发 workEnc、走 HTTP 两跳即可」——中间页**确实**有 `#workEnc`，但**裸 HTTP 拿不到那个中间页**（返回登录页），所以必须用 WebView 去拿。

### 3. 已用真实数据验证的解析规则（现有代码正确，不用改）

<li data="https://mooc1.chaoxing.com/mooc-ans/mooc2/work/task?courseId=…&workId=…&enc=…"
    aria-label="实践报告1 ; 未交"> … </li>

空作业课程返回 200 + 「0/0 暂无作业」且无 `<li data>`，可与「结构变化」区分。

### 5. 题目/题干真实结构（已实测，做「蒙版」单选题作业得出）

原始 DOM 存档：`.workbuddy/research/samples/work-question.html`

**`.TiMu` 不是单题容器，是整卷**：1 个 `.TiMu` 里装了 12 道题（`mark_name ×12`、`stem_answer ×12`、`answerBg ×26`）。把它当单题解析只能拿到第 1 题，答案必然串题——这是以前解析全错的根源。

每题结构：

```html
<h3 class="mark_name colorDeep fontLabel" data="405975556">1. <span class="colorShallow">(单选题)</span>
  <p>题干正文…</p>
</h3>
<input type="hidden" id="answertype405975556" value="0">
<input type="hidden" id="answer405975556" value="">
<div class="stem_answer qtDetail">
  <div class="clearfix answerBg workTextWrap" onclick="addChoice(this);"
       role="radio" aria-label="A 显示选择" qid="405975556" qtype="0">
    <span class="choice405975556 num_option fl" data="A">A</span>
    <div class="fl answer_p"><p>显示</p></div>
  </div> …
```

| 要什么 | 从哪取 |
|---|---|
| qid | `h3.mark_name[data]` |
| 题型 | `h3.mark_name` 内 `span.colorShallow` 文本；`qtype`：0=单选、3=判断（1=多选、2=填空未验到） |
| 题干 | `h3.mark_name` 去掉题型 span 后的文本 |
| 选项字母（展示/AI） | `aria-label` 首字符 或 `span.num_option` 文本 |
| 选项正文 | `div.answer_p` 文本 |
| 点选 | 点 `div.answerBg`（自带 `onclick="addChoice(this)"`） |
| 填空 | `tiankongsize<qid>` + `textarea`/UEditor |
| 提交值容器 | `input#answer<qid>` |

**判断题的坑**：26 个选项里有 10 个「显示字母 vs `data`」错位，全部是判断题——页面显示 `true`/`false`，`data` 却是 `A`/`B`。选择题里两者一致。→ 判断题按显示文本归一成「对/错」，不能用 `data`。

**作业页无字体反爬**：所有打开的作业页 `font-cxsecret` 计数均为 0，题干可直接读文本 → AI 答题不需要截图（章节测验才需要，两者别混）。

**作答页无需「开始答题」**：`work/task?…` 会自动跳到 `work/dowork?…`，题目直接渲染。

## 0. 一句话结论

以前的项目卡在"获取作业"，绝大多数死在同一件事上：

> **`enc` 有五个，作业列表必须用 `workEnc`。用中间页那个页面通用 `enc`，服务器就回「您没有权限」。**

配套还有四个伴随参数（`openc` / `t` / `stuenc` / `isdisplaytable`）少一个就可能「参数验证不通过」。而 `workEnc` 和 `stuenc` 是**服务端在课程中间页现下发的、与会话绑定**的，不能写死在配置里、不能人工抄一次用一年。

所以本方案的核心主张只有一条：

> **enc 不是配置项，是运行时从课程中间页现取的中间产物。** 每门课多花一次约 200 ms 的请求，换来永不过期的作业列表。

## 1. 归因：四种典型死法

| # | 现象 | 真实原因 | 证据 |
|---|---|---|---|
| 1 | 作业列表返回「您没有权限」 | 中间页服务端渲染了 5 个隐藏 input：`enc` / `openc` / `oldenc` / `workEnc` / `examEnc`。**作业列表的 `enc=` 必须取 `workEnc`**，取页面通用 `enc` 就无权限 | Xuexitong-mcp 逆向备忘（标注"经真实账号实测验证 2026-09"） |
| 2 | 「参数验证不通过」/ 空白页 | 除 `enc` 外还要 `openc`、`t`（毫秒时间戳）、`stuenc`、`isdisplaytable=2`，少一个都过不去 | 同上；CSDN 抓包样本 `...&ut=s&t=1742980068628&stuenc=...&enc=...` |
| 3 | 有时成功、有时失败；换设备/换会话就全挂 | `stuenc` 与课程页 `enc` 与会话绑定，手拼 URL 会让服务端判定「参数验证不通过」 | course-ai-helper 适配笔记原文：「课程页的 t= 时间戳和 enc= 是会话绑定的，手拼 URL 会得到『参数验证不通过 / 无效的参数』——必须从真实点击链路拿」 |
| 4 | 第一次能用，第二天全挂 | 主流开源方案（chaoxing-mcp）的做法是让**人**去浏览器抄 `stuenc/enc` 存进缓存表，号称"按课程固定"。本质是把配置成本转嫁给用户，且前提本身不稳 | chaoxing-mcp README 的 `xt_seed_enc` 设计 |

第 4 条正是我们自己「主方案 v1.0」里写错的地方（原方案第 3.2 节写"按课程跨会话稳定、抓一次永久有效"）。现已更正，见第 5 节。

## 2. 真实链路（每门课 2 次 HTTP，不需要 WebView）

```
[1] GET  i.chaoxing.com/base
         取：fid、账号、学校名（也用于判定登录态是否失效）

[2] GET  mooc1-api.chaoxing.com/mycourse/backclazzdata?view=json&rss=1
         取：channelList[].content.course.data[] -> courseId / classId / cpi / name
    兜底 GET mooc2-ans.chaoxing.com/mooc2-ans/visit/courselistdata?courseType=1&courseFid=<fid>
         （HTML，课名在链接后方 course-name span 的 title 里）

     —— 以下每门课各两跳 ——

[3] GET  mooc1.chaoxing.com/visit/stucoursemiddle
           ?courseid=&clazzid=&cpi=&ismooc2=1&v=2
         取：页面里 5 个隐藏 input 的 value
             <input type="hidden" id="enc"     value="...">   页面通用 enc
             <input type="hidden" id="openc"   value="...">
             <input type="hidden" id="oldenc"  value="...">
             <input type="hidden" id="workEnc" value="...">   作业 tab 专用  <- 关键
             <input type="hidden" id="examEnc" value="...">   考试 tab 专用

[4] GET  mooc1.chaoxing.com/mooc2/work/list
           ?courseId=&classId=&cpi=&ut=s
           &openc=<openc>
           &enc=<workEnc>            <- 不是页面 enc
           &t=<当前毫秒时间戳>
           &stuenc=<页面 enc>
           &isdisplaytable=2
         取：<li onclick="goTask(this);" data="<详情页直链>" aria-label="标题 ; 状态">

[5] GET  <第 4 步 li 的 data 属性>
         形如 mooc1.chaoxing.com/mooc-ans/mooc2/work/task
              ?courseId=&classId=&cpi=&workId=&answerId=&enc=
         取：题量 / 满分 / 作答起止时间（"作答时间: 10-08 08:00 至 10-15 23:59"，后者即截止）/ 得分

[6] 作答页（WebView，仅供回填，不参与列表获取）
```

要点：
- 作业条目的 `data` 属性本身带**独立 enc**，详情页直接用它，不需要再拼参数。
- 整条链只用 GET，不提交任何表单。
- 状态文字就在 `aria-label` 里（形如 `实验2 ; 未交`），比去 DOM 深处找 span 稳得多。

## 3. 参数对照表（这一页是整份方案的核心）

| 参数 | 取值来源 | 缺失 / 用错的后果 |
|---|---|---|
| `courseId` `classId` `cpi` | 第 2 步课程列表 | 直接查不到课 |
| `ut` | 固定 `s` | 无权限 |
| `enc` | **中间页 `#workEnc`** | 用 `#enc` → 「您没有权限」 |
| `stuenc` | 中间页 `#enc`（注意：是通用的那个） | 缺 → 「参数验证不通过」 |
| `openc` | 中间页 `#openc` | 社区样本里没有也能成功，但保留更稳；探针会给出你账号的真实答案 |
| `t` | 请求发出时的毫秒时间戳 | 用陈旧值 → 部分场景判定失败 |
| `isdisplaytable` | 固定 `2` | 缺 → 可能拿到移动版结构，解析器对不上 |

注意 `enc` 与 `stuenc` 的值**互换了来源**：`enc` 要用 `workEnc`，`stuenc` 才用页面通用 `enc`。这一步错位是绝大多数失败的直接原因，也是我把它单独列成表的原因。

## 4. 制作步骤 S0 – S7

每一步都是「可机械验证」的，不通过就不进下一步。

### S0　跑通探针（今天就能做，0.5 小时）

产出：`tools/probe-homework.mjs`（已写好并自检 22/22 通过）

它做的事：按上面 [1]→[5] 全链路走一遍，把每一跳的原始响应存到 `.workbuddy/research/samples/`，并对**每门课试四种参数组合**，告诉你哪种组合在你的账号上真的能拿到作业：

```
V1 完整：enc=workEnc + stuenc + openc + isdisplaytable=2
V2 去 openc / isdisplaytable
V3 enc 用页面通用 enc        <- 用来验证"必须用 workEnc"这个说法
V4 只留四件套（最保守）
```

用法：

```bash
# 1) 浏览器登录学习通，F12 -> Network -> 任意请求 -> 复制整串 Cookie
# 2) 存到 E:\Codex wenjian\学习通\.workbuddy\research\cookie.txt
# 3) 跑
"C:/Users/Administrator/.workbuddy/binaries/node/versions/22.22.2-6/node.exe" \
  tools/probe-homework.mjs
```

验收标准（四条全中才算过）：
1. 第 1 步打印出你的账号与学校名，不是被重定向到登录页；
2. 第 2 步拿到 ≥ 1 门课，且 `cpi` 不为空；
3. 至少一门课的中间页抽到了 `workEnc`；
4. 至少一门课在某个 V 组合下返回 ≥ 1 条 `<li data="...">`。

如果第 4 条只有 V1 通，说明社区结论在你的账号上成立；如果 V3 也通，说明你这账号的学校实例没做严格校验（那就更省事）。**这个结论必须用你的账号测，别人测过不算。**

### S1　会话层（半天）

- Cookie 从密文存储注入 OkHttp `CookieJar`，与 WebView 的 `CookieManager` 双向同步。
- 失效判定：`finalUrl` 命中 `passport2.chaoxing.com/login`，或响应含「请先登录/未登录」，统一抛 `NeedLogin`。
- 全局串行 + 每 host 最小间隔 300 ms；`mooc1-1` 首连已知常被 RST，首次重试一次。

验收：登录后杀掉进程重开，S1 仍判定为有效；手动改坏 Cookie 后判定为 `NeedLogin`。

### S2　课程列表（半天）

主源 JSON，兜底 HTML，产出统一的 `Course(courseId, classId, cpi, name)`，按 `courseId+classId` 去重。

验收：课程数与你网页版左侧课程数一致；`cpi` 无一为空。

### S3　enc 包抓取（核心，1 天）

```kotlin
data class EncPack(val enc: String, val openc: String, val workEnc: String, val examEnc: String, val fetchedAt: Long)

suspend fun fetchEncPack(courseId: String, classId: String, cpi: String): Result<EncPack>
```

- 解析方式：正则遍历所有 `<input>` 标签，逐标签读 `id` 与 `value` 两个属性（**不要假设属性顺序**，探针里两种顺序都测过）。
- 缓存：按 `courseId+classId` 存 Room，TTL 12 分钟。
- 遇到「您没有权限 / 参数验证不通过」→ **作废该项缓存，重取一次**，且只重取一次（防死循环）。

验收：连跑 10 门课，`workEnc` 获取成功率 100%；把某门课的缓存手工改成错误值，能自动重取并恢复。

### S4　作业列表（核心，1 天）

- 按 V1 组装参数，失败按 V2 → V4 顺序退化（探针已给出你账号的真实顺序）。
- 每次请求 `t` 取当前毫秒，不复用。
- 并发 1，失败不重试超过 1 次。

验收：与网页版作业 tab 逐条对照，标题、状态、条数完全一致。

### S5　解析与状态归一（1 天）

- 行解析：遍历 `<li>`，取同标签上的 `data` 与 `aria-label`；`data` 必须含 `chaoxing.com`，否则跳过（防把无关 li 当作业）。
- 从 `data` 直链里拆 `workId` / `answerId` / `enc`。
- 状态归一：

| 页面文字 | 归一为 | 计入未完成 |
|---|---|---|
| 未交 / 未提交 / 未开始 | `PENDING` | 是 |
| 待批阅 / 已交 / 已提交 / 待评 | `SUBMITTED` | 否 |
| 已完成 / 已批阅 / 已评分 | `GRADED` | 否 |
| 已过期 / 已截止 | `OVERDUE` | 视截止前是否已交而定 |

- 首页数字 = Σ `PENDING`（含已过期未交）。

验收：单测覆盖上述四类文字与未知文字的兜底；用真实数据比对首页数字与人工点数一致。

### S6　详情与截止时间（半天）

- 详情只对 `PENDING` 的作业按需请求，不做全量预取（10 门课 30 份作业逐份查会慢且招风控）。
- 抽取「作答时间: MM-DD HH:MM 至 MM-DD HH:MM」，后半段即截止。
- **注意：学习通不给年份。** 按"与今天最近的年份"补全；跨年作业可能排错序，页面上标注"约"即可，不要假装精确。

验收：随机抽 5 份作业，截止时间与网页版一致（允许跨年项标注）。

### S7　失效重取与三级兜底（1 天）

```
作业列表为空 / 被拒
  ├─ 有 <li> 但无 data        -> 判"页面结构变化"，走 WebView 渲染后抓 DOM
  ├─ 无 <li>                  -> 判"确实没有作业"，正常空态
  ├─ 「您没有权限」            -> 作废 enc 缓存，重取中间页，重试 1 次
  ├─ 「参数验证不通过」        -> 退化参数组合 V2/V3/V4
  └─ 全挂                     -> 隐藏 WebView 直接打开 work/list 的完整 URL，抓 DOM
```

验收：人为构造上述四种失败各一次，每种都能走到预期分支且不崩。

## 5. 缓存与有效期（更正主方案 v1.0 的错误假设）

| 数据 | TTL | 失效触发 | 说明 |
|---|---|---|---|
| 课程列表 | 30 分钟 | 手动刷新 | 一学期基本不变 |
| **enc 包** | **12 分钟** | 任何「无权限/参数验证不通过」 | 原名"永久缓存"是错的，改为会话级短缓存 + 失败即重取 |
| 作业列表 | 5 分钟 | 下拉刷新 | 控制请求量，避免风控 |
| 作业详情 | 不缓存 | - | 按需实时取 |

请求预算：10 门课一次全量刷新 = 1（base）+ 1（课程）+ 10×2（中间页+列表）= **22 次 GET**，串行 300 ms 间隔约 8 秒。这就是"首页数字"的刷新成本，可接受。

## 6. 失败矩阵

| 现象 | 判定 | 处理 | 用户看到 |
|---|---|---|---|
| 302 → passport | Cookie 失效 | 全局重登 | 「登录已过期」+ 一键重登 |
| 「您没有权限」 | enc 错/过期 | 作废 + 重取 + 重试 1 次 | 无感 |
| 「参数验证不通过」 | 参数缺 | 退化组合 | 无感 |
| 200 且有 `<li>` 无 `data` | 结构改版 | 走 WebView 兜底 | 无感（慢一点） |
| 200 且无 `<li>` | 真的没作业 | 正常空态 | 「该课程暂无作业」 |
| 中间页无 `workEnc` | 该课未开通作业 / 版本差异 | 标记该课 enc 不可用 | 「本课程需在网页端查看」 |
| 429 / 风控 | 太快 | 指数退避，并发降 1 | 「请求过于频繁」 |
| 网络异常 | - | 展示缓存 + 重试 | 「已展示 3 分钟前的数据」 |

## 7. 代码骨架

```kotlin
// data/remote/chaoxing/ChaoxingClient.kt
class ChaoxingClient(private val http: OkHttpClient, private val jar: CookieJar) {

    suspend fun fetchCourses(): ChaoxingResult<List<Course>>          // S2 双源
    suspend fun fetchEncPack(c: Course): ChaoxingResult<EncPack>     // S3
    suspend fun fetchWorks(c: Course, enc: EncPack): ChaoxingResult<List<Work>>  // S4
    suspend fun fetchWorkDetail(w: Work): ChaoxingResult<WorkDetail> // S6
}

// S4 的参数组装（唯一允许拼 URL 的地方，集中在一处便于改版时修改）
private fun buildWorkListUrl(c: Course, p: EncPack, variant: Int): String {
    val t = System.currentTimeMillis().toString()
    val base = mapOf(
        "courseId" to c.courseId, "classId" to c.classId, "cpi" to c.cpi,
        "ut" to "s", "t" to t,
        "enc" to if (variant == 3) p.enc else p.workEnc,   // 关键差异
        "stuenc" to p.enc,
    )
    val extra = when (variant) {
        1 -> mapOf("openc" to p.openc, "isdisplaytable" to "2")
        2 -> emptyMap()
        3 -> emptyMap()
        else -> emptyMap()
    }
    return "$WORK_LIST?" + (base + extra).entries.joinToString("&") { "${it.key}=${it.value}" }
}
```

约束：
- URL 拼装只出现在 `buildWorkListUrl` 一个函数里。学习通改版时改这一个函数 + 对应单测，不改业务。
- 解析器全部是无 Android 依赖的纯函数（`input: String -> output`），JVM 单测直接喂 HTML 字符串。
- 探针（Node）与 App（Kotlin）的解析规则必须同步；探针里已验证的 fixture 直接搬成 Kotlin 单测用例。
