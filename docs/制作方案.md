## 3. 三个关键技术判断

### 3.1 登录：走 WebView，不做密码直连

| 方案 | 优点 | 致命缺点 | 结论 |
|---|---|---|---|
| A. 账号密码直连（AES 加密 POST `/fanyalogin`） | 快、可无界面刷新 | 必须存密码；遇验证码 / 双因子直接死；加密密钥随改版失效 | 不采用 |
| B. WebView 内登录，取 Cookie | 不存密码；验证码 / 扫码 / 双因子全由用户自己过；改版免疫 | 首次要多点两下 | **采用** |
| C. 扫码登录 | 体验好 | 实现成本高于收益 | 后续可选 |

落地细节：
- 用 `androidx.webkit` 承载登录 WebView，加载 `https://passport2.chaoxing.com/login`，PC UA（PC 页面结构比移动页稳定，且 `enc/stuenc` 只在 PC 版出现）。
- 判定登录成功：轮询 `CookieManager.getCookie("https://.chaoxing.com")` 是否同时含 `_uid` 与 `fid`。
- 成功后把整串 Cookie 加密写入本地，并同步给 OkHttp 的 `CookieJar`。
- **不保存密码**。可选择只保存手机号（方便下次填充），用户可关闭。

### 3.2 数据：HTTP 直连（已修正，详见专项文档）

> **本节已被《作业获取方案-制作步骤.md》取代。** 原判断"`enc` 抓一次可永久复用"是错的，现更正如下。

真实链路（每门课 2 次 GET，**不需要 WebView**）：
1. `GET i.chaoxing.com/base` → `fid` / 账号 / 登录态。
2. `GET mooc1-api.chaoxing.com/mycourse/backclazzdata?view=json&rss=1` → 课程四要素（JSON，兜底 HTML 源 `mooc2-ans.../visit/courselistdata?courseType=1&courseFid=<fid>`）。
3. `GET mooc1.chaoxing.com/visit/stucoursemiddle?courseid=&clazzid=&cpi=&ismooc2=1&v=2` → 服务端渲染的 5 个隐藏 input：`enc` / `openc` / `oldenc` / `workEnc` / `examEnc`。
4. `GET mooc1.chaoxing.com/mooc2/work/list?courseId&classId&cpi&ut=s&openc&enc=<workEnc>&t=<毫秒>&stuenc=<enc>&isdisplaytable=2` → `<li data="详情直链" aria-label="标题 ; 状态">`。
5. 详情直接走 `data` 直链。

关键更正：**`enc` 必须取中间页的 `workEnc`，不是页面通用 `enc`**（取错即「您没有权限」）；`stuenc` 才用通用 `enc`。两者来源互换，是此前项目卡死的直接原因。`enc` 包改为会话级短缓存（TTL 12 分钟）+ 失败即重取，不再假设"永久有效"。

三级兜底降级为：参数组合退化 → 隐藏 WebView 渲染抓 DOM → 浏览器打开原页面。每门课不再有 2–3 秒的初始化成本。

未完成数量的统计口径（必须写死，否则数字对不上）：

| 作业状态 | 是否计入「未完成」 |
|---|---|
| 未交（含已过期未交） | 计入 |
| 待批阅（已提交） | 不计入 |
| 已完成 / 已批阅 | 不计入 |

首页数字 = Σ 各课程计入条数。缓存 5 分钟内不重复请求；下拉刷新强制重算。

### 3.3 答题：AI 出答案，人做提交

链路：作答页 → 原生解析题目 → 分批问 AI → 结构化校验 → 逐题卡片 → 一键回填 → **用户自己点提交**。

三条硬边界（不是道德姿态，是工程判断）：
1. **不自动提交。** 提交不可回滚，一旦 AI 答错就是既成事实；把最后一下留给用户，翻车成本从「作业废了」降到「改一个字」。
2. **不碰考试。** 考试页有 `FLAG_SECURE` 与切屏检测，做进去必然引发账号风险，收益为零。
3. **不刷课、不签到。** 与「查作业 + 辅助答题」无关，纯属范围蔓延。

## 4. 架构与项目结构

### 4.1 分层（依赖只向下，单向）

```
ui (Compose Screen)
  ↓
viewmodel (状态机 + 意图)
  ↓
repository (缓存策略 / 并发控制 / 错误翻译)
  ↓
datasource ──┬── remote/chaoxing (OkHttp + Jsoup + CookieJar)
             ├── remote/ai       (OpenAI 兼容 SSE 客户端)
             ├── webview         (隐藏 WebView 抓取 + 注入回填)
             └── local           (Room + Keystore 加密偏好)
```

规则：Screen 不含业务判断；ViewModel 不碰 OkHttp/Jsoup；Repository 是唯一允许「缓存 + 网络」混合决策的层；datasource 之间不互相调用。

### 4.2 目录（单 module，按功能分包，不为分层再拆 module）

```
app/src/main/java/com/xxt/study/
  App.kt                      Application：DI 容器装配、崩溃兜底
  core/
    di/Container.kt            手写轻量依赖容器（不引 Hilt）
    crypto/SecretStore.kt      AndroidKeyStore AES-GCM
    net/OkHttpProvider.kt      单例 + 拦截器（UA / 节流 / 重试 / 日志脱敏）
    net/PersistentCookieJar.kt
    result/ChaoxingResult.kt   Ok / NeedLogin / ParseFailed / RateLimited / Network
    ui/                        色板、字体、间距、图标（ImageVector 自绘）、通用状态组件
  feature/
    login/                     LoginScreen + LoginViewModel（WebView 登录）
    home/                      HomeScreen + HomeViewModel（未完成数量）
    course/                    CourseListScreen / WorkListScreen
    work/                       WorkDetailScreen（AI 答案卡片）+ AnswerSheet（WebView 回填）
    settings/                  AiSettingsScreen / AboutScreen
  domain/model/                Course / Work / Question / AnswerItem / AiProfile
  data/
    remote/chaoxing/           CourseApi / WorkApi / HtmlParser
    remote/ai/                 AiClient / PromptBuilder / SseParser / AnswerValidator
    webview/                   HiddenFetcher / AnswerInjector / InjectScript
    local/                     AppDatabase / 各 Dao / Prefs
    repo/                      SessionRepo / CourseRepo / WorkRepo / AiRepo
```

硬约束：单文件 ≤ 300 行；`App.kt` 只装配零业务；解析与校验这类纯逻辑必须是**无 Android 依赖的纯函数**，配 JVM 单测（这是本项目最值得写测试的地方，因为平台改版时靠单测快速定位）。

### 4.3 依赖清单（体积优先，逐个说明为什么值得）

| 依赖 | 用途 | 取舍理由 |
|---|---|---|
| compose ui / foundation / material3 | UI | 已在缓存，UI 迭代最快 |
| activity-compose、lifecycle-runtime-compose | 宿主与状态 | 必需 |
| kotlinx-serialization-json | AI 与 JSON | 无反射，比 Gson 小 |
| kotlinx-coroutines-android | 异步 | 必需 |
| okhttp | 网络 | 已在缓存；不引 Retrofit（接口少，手写请求更省） |
| jsoup | HTML 解析 | **本项目最关键的依赖**，作业页只能解析 DOM，自己写正则不可维护 |
| room3 + ksp | 课程 / 作业 / enc / AI 配置缓存 | 已在缓存，3.0.3 |
| androidx.webkit | WebView 增强 API | 登录与抓取必需 |
| junit | 纯函数单测 | 必需 |

明确不引：Hilt / Dagger（手写容器 40 行足够）、Retrofit、Coil（图标全自绘）、Paging（列表最多几十条）、Compose Navigation（页面只有 6 个，用密封类 + 一个 `AnimatedContent` 自己管，省一个依赖且跳转更可控）、Material Icons 扩展包（几十 MB，只用得到十几个图标）。

## 6. 数据模型

### 6.1 领域模型

```kotlin
data class Course(
    val courseId: String, val classId: String, val cpi: String,
    val name: String, val teacher: String,
    val encState: EncState,          // Cached / None / Failed
    val pendingCount: Int,           // 未完成作业数
    val syncedAt: Long,
)

data class Work(
    val workId: String, val courseId: String, val classId: String,
    val title: String, val status: WorkStatus,
    val endAt: Long?,                // 截止时间，null=不限
    val remainSeconds: Long?, val detailUrl: String,
)

enum class WorkStatus { PENDING, SUBMITTED, GRADED, OVERDUE_PENDING }

data class Question(
    val index: Int, val type: QuestionType,
    val stem: String, val options: List<Option>,   // 单选/多选/判断用
    val blankCount: Int = 0,                        // 填空用
)

enum class QuestionType { SINGLE, MULTIPLE, JUDGE, FILL, SHORT }

data class AnswerItem(
    val index: Int, val answer: String,
    val confidence: Int,             // 0-100，AI 自评
    val reason: String,              // 一句话理由
    val valid: Boolean,              // 结构校验是否通过
)

data class AiProfile(
    val id: Long, val name: String,
    val baseUrl: String, val model: String,
    val temperature: Double, val maxTokens: Int, val timeoutSec: Int,
    val keyRef: String,              // 指向 Keystore 加密值，不存明文
    val concurrency: Int = 1,
)
```

### 6.2 Room 表

| 表 | 主键 / 索引 | 说明 |
|---|---|---|
| `course` | `courseId + classId` 复合主键；索引 `syncedAt` | 课程 + `pendingCount` + enc 状态 |
| `enc_cache` | `courseId` | `stuenc`、`enc`、抓取时间（加密存储） |
| `work` | `workId` 主键；索引 `courseId`、`endAt` | 作业缓存 |
| `ai_profile` | 自增 id | 多套 AI 配置，`isActive` 唯一 |
| `answer_run` | 自增 id；索引 `workId` | 每次 AI 作答留底，便于回看与对比（可选关闭） |
| `sync_meta` | `key` | 上次全量同步时间、版本号 |

缓存策略：列表先读库秒开 → 后台刷新 → 差异更新。数据库单例、WAL 模式。

## 7. 网络层设计

### 7.1 OkHttp 配置

| 项 | 值 | 理由 |
|---|---|---|
| 单例 | 一个 `OkHttpClient`（学习通与 AI 各自一个，AI 用更长读超时） | 连接池复用 |
| UA | Chrome on Windows（PC 版） | PC 页面才带 `enc/stuenc`；移动版结构不同 |
| CookieJar | 自定义持久化实现，读写加密文件 | 与 WebView 的 Cookie 双向同步 |
| 超时 | 学习通 connect 10s / read 20s；AI connect 15s / read 120s（流式） | 分工不同 |
| 重试 | 仅幂等 GET；指数退避 2 次；`mooc1-1` 首连 RST 已知 → 立即重试 1 次 | 社区实测经验 |
| 节流 | 全局串行 + 每 host 最小间隔 300 ms | 降低风控概率 |
| 日志 | debug 构建打印 URL 与状态码；Cookie / Key / 题干正文一律脱敏 | 防泄漏 |

### 7.2 接口清单

| 用途 | Method | 地址 | 认证 | 关键参数 |
|---|---|---|---|---|
| 登录（WebView 内） | GET | `passport2.chaoxing.com/login` | - | 用户手输 |
| 登录态校验 | GET | `i.chaoxing.com/base`（或个人中心） | Cookie | 看是否 302 回 passport |
| 课程列表 | POST | `mooc1-1.chaoxing.com/visit/courselistdata` | Cookie | 表单 |
| 作业列表 | GET | `mooc1.chaoxing.com/mooc2/work/list` | Cookie | `courseId / classId / cpi / ut=s / stuenc / enc` |
| 作业详情（题干） | GET | `mooc2-ans.chaoxing.com/mooc2/work/view` | Cookie | `courseId / classId / cpi / workId / answerId / enc` |
| 作答页（回填目标） | GET | `mooc2-ans.chaoxing.com/mooc2/work/dowork` | Cookie | 同上 |
| AI 对话 | POST | `{baseUrl}/chat/completions` | Bearer | OpenAI 兼容 |

> 上表中 `view` / `dowork` 的具体路径与参数以 M0 真机抓包为准，方案先锁定「有这两个环节」，不锁死路径字符串——这是唯一允许在实现期调整的部分。

### 7.3 统一错误模型

```kotlin
sealed interface ChaoxingResult<out T> {
    data class Ok<T>(val data: T) : ChaoxingResult<T>
    data object NeedLogin : ChaoxingResult<Nothing>       // 302 回 passport / 401
    data class ParseFailed(val url: String, val reason: String) : ChaoxingResult<Nothing>
    data class RateLimited(val retryAfterSec: Long?) : ChaoxingResult<Nothing>
    data class Network(val cause: Throwable) : ChaoxingResult<Nothing>
}
```

Repository 负责把它翻译成 UI 文案 + 可执行动作，UI 层不出现任何 HTTP 概念（不出现 401、403、`IOException` 字样）。

## 8. 登录态管理

| 状态 | 触发 | UI 表现 |
|---|---|---|
| `LoggedOut` | 首启无 Cookie / 用户主动退出 | 登录页，展示「在下方页面登录学习通，登录后自动返回」 |
| `Verifying` | 登录 WebView 检测到 Cookie | 全屏轻量进度，最长 15 s |
| `Valid` | Cookie 同时含 `_uid` + `fid` | 进入首页 |
| `Expired` | 任一接口返回 `NeedLogin` | 全局面板「登录已过期」，一键重登，重登后回到原页面 |

要点：
- Cookie 加密存（AES-GCM，Keystore 生成密钥，`allowBackup=false`），不写明文 SharedPreferences。
- 退出登录 = 清 Cookie + 清 `enc_cache`（enc 与学生绑定，换账号必须重抓）。
- 401 不静默重试，避免把用户锁在循环里。
- 不做「后台保活自动续期」——学习通无 refresh token，只能等失效后重登。

## 9. AI 答题链路

### 9.1 设置页（独立一级页面）

分四组，每组一个说明段落 + 就地「测试连接」：

| 分组 | 字段 | 备注 |
|---|---|---|
| 接口 | BaseURL、API Key、模型名 | BaseURL 自动补 `/v1`；Key 输入框默认掩码，可点眼睛查看 |
| 参数 | 温度（0–1，默认 0.3）、最大输出 token、超时秒、并发（默认 1） | 温度默认偏低，答题要稳不要飘 |
| 提示词 | 系统提示词模板（可编辑，带「恢复默认」） | 让用户自己调，比内置死文案更实用 |
| 档案 | 保存 / 重命名 / 删除 / 设为当前 | 常见组合一键填：DeepSeek、通义、智谱、Ollama 本地 |

「测试连接」行为：发一条最小请求（`max_tokens=8`，内容 "ping"），返回则显示「连接正常 · 模型：xxx · 延迟 420 ms」，失败则给出分类原因（Key 无效 / 地址不可达 / 模型不存在 / 超时）。

Key 存储：Keystore AES-GCM，密文入文件，明文只在内存短暂存在；日志与崩溃上报一律不含 Key。

### 9.2 答案生成流程

```
作业详情页
  → 解析题目（Jsoup：题干容器 / 选项 / 题型 / 空数）
  → 分批（每批 ≤ 8 题，避免长作业被截断）
  → PromptBuilder：
        system: 你是答题助手，只输出 JSON，不解释，不寒暄
        user:   [题型/题干/选项] ×N
  → AiClient（SSE 流式，逐题增量渲染，用户不用干等）
  → AnswerValidator（纯函数）
  → 逐题卡片
```

### 9.3 答案校验（纯函数，重点单测对象）

| 题型 | 校验规则 | 不合格处理 |
|---|---|---|
| 单选 | 必须是选项字母集里的**单个**字符 | 标红「AI 答案异常」，保留原文供用户判断 |
| 多选 | 去重 + 排序 + 必须是选项集子集 | 同上 |
| 判断 | 归一为「对 / 错」（兼容 正确/错误/√/×/T/F） | 无法归一即判不合格 |
| 填空 | 空数与题干一致 | 数量不符标红 |
| 简答 | 非空且长度 ≥ 20 字 | 过短提示「建议补充」 |

不合格项**不隐藏、不自动改**，标红并附 AI 原文——用户有权看到 AI 到底说了什么。

容错：AI 返回非合法 JSON 时，降温度 0.1 重试一次；仍失败则展示纯文本原文并提示「未结构化，可复制后自行整理」。

### 9.4 回填（只填不交）

- 作答页 `dowork` 在 WebView 里打开，注入脚本按「题干文本模糊匹配 → 就近查找 input/textarea/选项 li」定位控件。
- 选择题点选对应 `li`；填空题 `value` 赋值并派发 `input` + `change` 事件；简答题写 `textarea.value`。
- 全部填完只做两件事：滚动到第一题、弹一条非阻塞提示「已填入 8/8 题，请核对后自行提交」。
- 定位失败率是这套方案的核心指标：M4 里对「单选 / 多选 / 判断 / 填空 / 简答」各取真实作业样本验证，任一题型低于 90% 就降级为「逐题复制」。
- 绝不查找、绝不点击任何提交按钮（代码层不出现提交 URL 常量，从架构上杜绝误触）。

## 10. UI 规范

| 项 | 决策 |
|---|---|
| 主色 | 墨蓝 `#2A5C8A`（学习通色系的沉稳版，非紫非渐变） |
| 强调 / 未完成数字 | 砖红 `#C0432F`（唯一高饱和色，只用在「未完成数量」和错误态） |
| 底板 | `#F5F6F8`；卡片纯白；分隔线 `#E6E8EB` |
| 文字 | 主 `#1B1F24` / 次 `#5C6470` / 弱 `#8C949F` |
| 字体 | 系统默认（`sans-serif`），数字用 `tabular-nums` 对齐 |
| 圆角 | 卡片 14 dp，按钮 10 dp，芯片 8 dp |
| 图标 | 全部 `ImageVector` 代码自绘，24 dp 网格 / 2 dp 描边，尺寸只用 16 / 20 / 24，**零 emoji、零图标库依赖** |
| 动效 | 转场 200 ms 位移淡入；列表项 120 ms 淡入；只用 `FastOutSlowIn`，禁弹簧回弹 |
| 深色模式 | 跟随系统，一套 token 两套值 |
| 无障碍 | 正文对比度 ≥ 4.5:1；所有可点区域 ≥ 48 dp；数字与进度带 `contentDescription` |

首页的信息层级刻意只有三层：**未完成数字（大）→ 一句状态说明 → 课程入口**。不放图表、不放推荐、不放广告位——「轻量」在视觉上就是「这一屏只有一个重点」。

## 11. 异常与空状态矩阵（逐条给文案与动作，不含糊）

| 场景 | 文案 | 动作 |
|---|---|---|
| 未登录 | 「登录后查看你的作业」 | 进入登录页 |
| Cookie 失效 | 「登录状态已过期」 | 一键重登（原地恢复） |
| 网络不通 | 「网络连接失败，已展示上次数据（3 分钟前）」 | 重试 / 查看缓存 |
| 请求超时 | 「学习通响应较慢」 | 重试 |
| 被限流 | 「请求过于频繁，请 30 秒后再试」 | 倒计时禁用刷新 |
| 无课程 | 「本学期暂无在读课程」 | 下拉刷新 |
| 课程无作业 | 「该课程暂无作业」 | 返回课程列表 |
| 全部完成 | 「当前没有待办作业，已交 23 份」 | 仍可进课程列表查看 |
| enc 未配置 | 「首次进入需初始化（约 3 秒）」 | 自动触发隐藏抓取，带进度 |
| enc 抓取失败 | 「本课程无法自动初始化」 | 降级到 L2 / L3 |
| 解析失败 | 「页面结构有变化，暂时无法解析」 | 在浏览器打开原页面 |
| AI 未配置 | 「先配置一个 AI 模型」 | 跳设置页 |
| AI Key 无效 | 「密钥无效或已过期」 | 跳设置页并聚焦 Key 输入框 |
| AI 超时 | 「模型响应超时」 | 重试（可切到更快的模型） |
| AI 格式异常 | 「答案格式异常，已展示原文」 | 复制原文 / 重新生成 |
| 作业已截止 | 「已过截止时间，仅供查看」 | 隐藏「填入」按钮 |
| 首启动加载 | 骨架屏（不用转圈） | - |
| 空列表 | 居中插画（自绘 24 dp 图标放大到 96 dp）+ 一句说明 + 一个动作 | - |

统一组件 `UiStateBox`：`Loading / Empty(icon,title,action) / Error(kind,retry) / Content`，每个列表页只挂一次，避免各页文案漂移。

## 12. 轻量化与流畅度

| 指标 | 目标 | 手段 |
|---|---|---|
| APK 体积 | ≤ 6 MB（release，R8 开启） | 单 module、无 OCR/无 ML Kit/无图标扩展包、`abiFilters=arm64-v8a`、资源裁剪 |
| 冷启动 | ≤ 1.2 s（中端机，含 Room 初始化） | 首页首帧不阻塞等网络；数据库懒初始化；禁用启动动画 |
| 首页数字出现 | ≤ 300 ms（有缓存时） | 先读 Room 出数字，再后台刷新 |
| 列表滚动 | 掉帧 ≤ 2 帧/秒 | `LazyColumn` + 稳定 key + 避免在 item 内做解析 |
| 内存峰值 | ≤ 150 MB | WebView 用完即 `destroy()`，同一时刻最多 1 个隐藏 WebView |
| 全量刷新 | 10 门课 ≤ 8 s | 课程并发 2、作业串行、失败不重试拖时间 |

WebView 是本方案唯一的重量级组件，因此明确约束：只在「登录」「抓 enc」「回填」三件事上存在，其余时间全部销毁，不做常驻。

## 14. 风险登记

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| `enc/stuenc` 会随会话变化，不只是按课程固定 | 中 | 每次要重抓，慢 3 秒/课 | L2 隐藏 WebView 兜底；抓取结果带有效期，过期静默重抓 |
| 学习通改版 HTML 结构 | 高（历史上频繁） | 解析全挂 | 解析器全部独立纯函数 + Jsoup 选择器集中在一处常量表；改版只改一处 + 单测兜底 |
| 触发风控 / 要求验证码 | 中 | 无法自动登录 | 登录本就走人工 WebView，天然可过；数据请求串行 + 节流 + 5 分钟缓存 |
| WebView 内学习通页面白屏 / 需特定 UA | 中 | 登录或回填失败 | M0 阶段固定 UA 并验证；备「用系统浏览器登录后粘贴 Cookie」的隐藏入口 |
| 作答页控件定位不稳 | 高 | 回填不可用 | 降级为逐题复制；回填率作为 M4 硬指标 |
| 账号安全与合规争议 | - | 用户自行承担 | App 内首次使用弹一次说明：不自动提交、不改动平台数据、仅本机直连、不上传账号 |
